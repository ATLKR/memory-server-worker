# Owner-only snapshot materialization (B2)

This contract describes the inactive owner-only B2 implementation; verification evidence is reported separately. The controlling scope is the root B2 adoption dated2026-09-15. This disposable local extension requires schema1–5, head foundation, protected provisioning, snapshot validation, ledger A and fact helper B1. It does not install caller snapshot dispatch, admission C, schema6, runtime injection or a production setup value. It must not be installed beside a serving schema5 authorizer.

## Exact legacy privilege additions

The existing head foundation supplies schema USAGE on memory_identity and memory_ops only. B2 adds USAGE on memory_control to projection owner so the prescribed organization/Space/deployment relation grants are usable. It adds no CREATE there and preserves the other schema ACL entries exactly.

The supported projection owner/caller roles have no outgoing role memberships. Installation rejects every pg_auth_members entry with either as member, including SET-only, INHERIT-only, ADMIN-only and indirect/custom-role first hops. Existing incoming provisioner and runtime membership rows remain unchanged; the separate dangerous-attribute and incoming owner SET/USAGE checks still apply. Rejected installations preserve the exact membership, role-attribute and default-ACL catalogue rows instead of revoking or repairing drift.

## Private observed plan and allocation contract

The private plan is recomputed from the stored event under the global fence and ordered row locks. It is never accepted as an input or a substitute for an applied assertion. Its exact result consists of event scalar metadata; a distinct source-reference map containing each five-tuple and a scalar grain key; one fact per account/claim/entity grain; normalized grant rows containing scalar source-reference keys; ordered SQL row observations/intended bindings/provenance decisions; protected provision decision fields; current usage/preservation observations; independently collected classifier flags; and measurement counters. No raw prior event bodies, complete account vector per alias, or copied head object per grant is returned. The candidate raw text/JSONB is local to the pass; prior event bodies are loaded and released one at a time.

The closed top-level keys are `event`, `sources`, `grains`, `currentComparisons`, `grants`, `rows`, `provision`, `usage`, `flags` and `metrics`. `event` holds only id/hash/checkpoint/Space/sequence/selected/lease scalars. `sources` maps decimal source revision to the five-tuple plus grainKey/currentRevision/firstSnapshotEventId; `grains` maps kind+resolved account/claim/entity locator to the exact B1 fact. `currentComparisons` retains only sourceRevision, firstSnapshotEventId, actualMatchesCurrent and candidateOrder for each current membership/credential. The complete prior fact/policy is compared with the actual signed row and applicable candidate while its one-event cache is live, then discarded before loading the next event. No full previous credential policy or prior account vector is retained across event groups. Each normalized `grants` entry contains its signed scalar grant fields and sourceRevisions, with policy obtained from its credential grain. `rows` entries contain kind, exact locator, sourceRevision, actual, intended, provenance, approval and preserved fields; actual/intended are complete schema5 rows, not copied event bodies. Provision contains only existing permitted decision columns. Usage is the actual five-column row or null. Flags and current comparison results are independently observed internal data, not supplied assertions or an execution trace. Metrics count actual candidate/prior validation calls, caller parses, body loads, distinct grain extractions and largest observed representations.

One account fact contains its provider vector once. Source tuples remain distinct even when they reference the same grain. SQL provider row observations contain each mapping once to support explicit writes and preservation. Existing Space data_policy has no schema5 size limit: compare it to the bounded candidate/provision inside SQL before retaining it. An incompatible policy contributes a structural-conflict scalar and is not copied into the returned row observation; a compatible policy remains exact for basis checks. These are real additional representations alongside the candidate and grain cache; compact output bytes do not imply a total allocator ceiling. The completed implementation report must measure plan/fact text sizes and actual validator/extractor/body-load calls rather than claiming zero-copy or total128KiB memory. One observed-plan return may copy its bounded result; no claim of linear total allocation follows without instrumentation.

Per pass, canonical(raw) validates once per distinct event and parses internally, then the caller parses its returned text once. Requested source and current mutable witness revisions use indexed locators. Prior witnesses group by first event and extract one representative fact per requested grain in that event. The pass retains candidate/grains, one prior body/grain cache and scalar source associations; P distinct witnesses can read P×131072 raw bytes. Independent classifier/receipt/final/deferred passes repeat these costs. Child guards use indexed event/generation/source membership, not a full graph pass per inserted child.

## Test-first execution checklist

The following are implementation gates, not current pass claims. Tests are grouped by their name prefix for bounded sequential execution.

1. `install`: missing SQL RED; exact inventory/ACL/column/policy/role/default/RI preservation; READ COMMITTED and fence-before-fresh-history observation; all A snapshot histories and contradictory/orphan metadata rejected; real heads preserved; collision/privilege/role/schema/policy drift rollback.
2. `apply`: actual personal and organization worker creation and exact TS receipt verification; all nine relations, real schema5 rows, full grant/head sets, new usage zeros and new cleanup false. No synthetic success fixture.
3. `reasons`: all19 real outcome pairs and precedence ties; missing/behind/current/newer sources; both source locators/namespace orders; sequence winner and later generation; expired/future/grant deadlines; immutable/provision/disposition conflicts; terminal/lifecycle/target denial; pending progress and exact historical replay.
4. `preserve`: complete retained basis/authorized first binding; later global source updates across Spaces; full current provider set, live unique locators and digest conflicts; historical provenance versus current reauth/cleanup/usage preservation; missing internal evidence unavailable; empty/omission/reappearance without revocation.
5. `guards`: bare A synthetic append rejection; exact grant/head sets, all five tuple fields and zero extras; orphan child writes; statement no-op mutations; pointer monotonicity; fault at every physical stage; final/deferred clock and role-restoration rollback.
6. `bounded`: representative near-wire snapshots, shared aliases and prior witnesses; actual extraction/validation/load counts and representation sizes; indexed plans with meaningful unrelated history; no new provider/grant cap, total-memory ceiling or provider SLO.

Final verification and source/evidence pins will be reported separately in work after all gates pass. Existing source files, package/registry, schema5 serving code and provider state remain outside author ownership.

The table/code owner and superuser remain trusted. Private raw schema5 INSERT/UPDATE rights can be exercised by deliberate owner SQL; a non-applied receipt guard checks event-linked B2 materialization state, not an execution trace of arbitrary unrelated owner statements. The supported worker classifies before its writes and propagates every unexpected error; immediate/final/deferred assertions check actual completed state. Fault tests cover all 18 written tables, late changes after receipt generation, and role-restored deferred checking. No caller-set flag, GUC, or marker proves a historical before-write observation.

The worker retains the exact five-column intended usage row through its final checks: four zeros for a new Space, or the complete actual current row for a retained Space. Completion additionally checks zero counters when this event is the Space's creation-provenance event. Later generations preserve current nonzero usage. Historical status/replay never invokes this creation-time assertion.

The worker also retains its original complete intended physical row bindings through the final post-receipt comparison. A newly observed plan cannot recover an earlier regional reauthentication or cleanup value after a permitted UPDATE fires another row trigger. Every physical row is therefore compared with the same saved binding both after writes and after receipt/final assertion. Immediate and deferred completion independently require a null reauthentication timestamp and false legacy cleanup flags when the actual entity provenance identifies this event as their creation event. Later generations preserve legitimate regional changes, and no deferred guard claims to reconstruct arbitrary retained-row history after the worker has returned.

An applied receipt seals its generation against all later append-only materialization children, including attempted reconstruction after privileged deletion. The immediate row guard resolves the owning event through a direct event ID or indexed generation key and rejects an already-applied receipt. Both pointer guards reject mutations attached to an already-applied event. The sole compatibility case is a BEFORE INSERT for an exactly equal existing mutable-current pointer: the worker's ON CONFLICT predicate performs no UPDATE; a real UPDATE still requires strict advancement and an uncompleted first-fact event. Existing deferred membership checks remain, and the initial full receipt assertion proves the exact signed set before sealing. No candidate body is parsed per child. Fault fixtures that disable triggers to remove/regress rows establish missing-state preconditions only; those privileged mutations are outside the supported production path.

Provider additions are allowed only when every actual regional mapping belongs exactly to the candidate and all required current subject facts have advanced consistently. A missing candidate mapping may then be inserted. Deferred provider provenance membership requires this exact generation's grant/account and full subject-head key; merely sharing an account with an old generation is insufficient.

Observed local resource cases include a104139-byte candidate with81 same-account providers: one actual canonical call, three actual B1 extractions, and a372071-byte compact JSON representation of the returned plan. The plan includes distinct scalar source keys plus actual/intended/provenance row representations; this measured expansion is not a total allocator bound. A prior8434-byte event and2291-byte candidate produced an8672-byte plan while the old credential scope was absent from the returned plan; one candidate and one prior body were loaded, with six distinct event/grain extractions. A300KB incompatible legacy Space policy is compared in SQL and excluded from the returned plan. These are local PGlite cases, not provider latency or peak-memory guarantees.
