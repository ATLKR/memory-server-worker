# Inactive complete snapshot validation

`snapshot-validation.sql` is an explicit disposable-test extension after actual migrations 0001–0005 and `head-foundation.sql`. It installs only four private pure functions in `memory_identity`. It is not a migration and the unchanged `seoul_projection_apply(text,text)` still rejects every snapshot.

The entry is `projection_v3_snapshot_canonical(text) RETURNS text`. On success it returns the identical canonical input string. Null, empty, over-131072-byte, malformed, noncanonical or incoherent input raises SQLSTATE `PP001`, message `seoul_projection_input_invalid`, without input-derived detail or hint. The database must use UTF8, as verified by the local fixture. PostgreSQL text already requires valid database encoding; a later transport must preserve and strictly decode the original UTF8 bytes before converting them to text. This file adds no transport entry or authentication.

The implementation mirrors the committed `src/release/seoul-projection-snapshot-codec.ts` and the amended account/grant/source contract. It reconstructs the exact closed top-level order:

`version,kind,eventId,sourceRevision,snapshotSeq,issuer,spaceId,selected,accounts,providerIdentities,emails,organizations,memberships,credentials,credentialPolicies,spaces,grants,lease`.

`projection_v3_snapshot_value(jsonb,text,bigint)` recursively reconstructs explicit field sequences and validated scalar values. Its internal schema tags are selected by the implementation, not the wire. JSONB parsing alone is not acceptance: reconstruction plus a C-collation exact text comparison rejects duplicate and escaped-duplicate keys, reordered/unknown/missing fields, alternate number and string spellings, negative zero, BOM and whitespace. JSONB is used only as an in-memory parsed structure and for internal map keys; `jsonb::text` is never transport serialization or hashing.

Safe positive revisions/sequences, nonnegative timestamps, exact lowercase UUID/digests, pinned issuer, bounded ASCII entity/Space IDs, canonical ASCII mailboxes, well-formed nonblank 512-UTF16-unit opaque subjects, exact residency policy/tags, and every array bound/order are checked. Embedded subject newlines/control characters and astral text remain representable. Mailbox validation reuses the committed closed head helper with an explicit email-lifecycle subject/address binding, so a newline inside a mailbox cannot become additional opaque subject text.

`projection_v3_snapshot_utf16(text)` emits integer UTF16 code units, splitting an astral scalar into its high/low surrogate pair. PostgreSQL array comparison gives exact JavaScript lexical order, including prefix order. All row/vector/string arrays use it. Provider issuers are constant and a repeated subject is an invalid composite identity even across different accounts; therefore strict subject order is equivalent to the codec's issuer/subject/account comparator followed by its composite uniqueness check. Email vectors independently sort each complete subject-plus-address key rather than inherit the subject order.

`projection_v3_snapshot_graph(jsonb)` validates only the supplied closed graph:

- Exactly one matching Space with personal-account XOR organization ownership; exact reachable account, organization, email and membership sets; every represented account has all its supplied composite identities.
- Exactly paired credential/policy/grant rows; unique token digests; at most 100 credentials per account; no duplicate live email address or organization/account membership tuple.
- Complete all-subject vectors for each credential account and, for an organization grant, complete same-address email vectors for every one of those subjects. Owner personal keys have null membership/email bindings and null organization/member/email heads. API keys require exact account/member/email/organization joins and direct organization authority.
- Selected/live Space, account, credential and organization; live membership and verified claim; exact credential/member expiry minimum. Supplied issued time is the reference. Read capability determines search; create plus write permission plus owner/admin determines ingest. At least one action must remain. Ordinary erase/retire are literal false; update/delete/export confer no additional regional action. Wildcard or at-most-50 explicit Space scope must permit this Space.
- Every dependency revision is at or below `sourceRevision`. Repeated `(kind,key)` streams have identical revision/event/source-digest tuples; distinct streams cannot reuse a revision or source event ID. A source event ID cannot equal the outer snapshot event ID. Different streams may share a source digest. This validator computes no digest and cannot establish source truth.
- A lease is exactly 60000 ms with safe arithmetic. Selected/deselected zero-grant graphs retain the exact required owner/organization structure and are valid data. Validation creates no lease or positive row.

No helper reads or writes an authority table, checks current heads/tombstones, queries database time, inserts an event/receipt, changes a snapshot sequence, or proves completeness against central D1. It cannot make schema5 retained rows ready, provision a Space, admit a PAT, or enable share-only authority. Full positive apply and its current-head, provisioning, retained-row, terminal-state, lease/time and public-admission checks remain separate work.

All four functions are `IMMUTABLE`, `SECURITY INVOKER`, owned by `memory_projection_owner`, with pinned `search_path=pg_catalog` and owner-only EXECUTE. The caller, runtime, old migration owner, fixture provisioner, anonymous/authenticated and disposable login receive no execution grant. Installation temporarily restores privileged SET edges and schema CREATE, then returns those exact existing fixture edges/ACLs; it creates no role, default privilege, table or policy. Installation is not a general-purpose provider provisioning script.

`test/postgres/seoul-projection-snapshot-validation.test.mjs` uses real schema5/PGlite with independent complete zero wire, independent populated field-order expectations, the committed codec as differential reference, coherent owner/org/multi-account/multi-identity fixtures, source collision regressions, reachable alias uniqueness failures, and all 256 capability/permission/direct-role combinations. It proves exact 131072-byte acceptance and 131073-byte refusal; 100 compact credentials are 130158 bytes and accepted. The 101-credential fixture is 131455 bytes, so its refusal is also a byte-bound case, not isolated count-only evidence.

The tests exercise actual direct SQL/SET SESSION AUTHORIZATION and compare all old memory-table rows, table ACL/RLS flags, namespace ACLs, role memberships, default ACLs and function definitions before/after extension installation and validation. Existing head state/receipts are populated for this comparison, and main apply still rejects the snapshot. Local evidence uses PostgreSQL 18.3 in PGlite 0.5.8 with Node 24.19.0 and UTF8. It is not evidence for historical provider PostgreSQL 17.6, independent concurrent sessions, deployment, network transport, lease availability or a performance SLO.
