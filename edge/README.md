# Gate the existing management page

This Worker checks an interactive browser session before forwarding GET `/manage` to the existing backend. It also handles prefixed paths such as `/region-one/manage`. A PAT cannot grant frontend access. The backend continues to own OAuth, sessions, and API authorization.

1. Run `npm run test:management-gate` with the repository's supported Node version. The check uses synthetic requests and a controlled binding. It makes no live backend calls.
2. Copy `wrangler.example.jsonc` to an operational configuration outside the checkout. Set `main` to the absolute path of `management-gate.ts`. Bind `MEMORY_API` to the backend that already serves these management paths. Set `PUBLIC_ORIGIN` to its exact HTTPS origin without a trailing slash.
3. Verify current route ownership and enumerate every management hostname, regional path, alias, workers.dev endpoint, and preview URL. Add only management routes for that backend. Keep the trailing `*` so query strings also match. The handler gates paths ending exactly in `/manage`. Other paths and methods pass to the same backend unchanged. HEAD currently retains the backend's 405 response. New frontend paths require matching code and route updates.
4. Build with the installed Wrangler using `wrangler deploy --dry-run --config <operational-config>`. After deployment approval, verify anonymous, PAT-only, expired-session, and interactive-session requests on every public management entry. Verify the existing login and callback, plus API, CLI, HEAD, POST, and websocket behavior. Remove only the newly recorded routes to roll back to the original backend responder.

The gate probes the same origin and public prefix at `/v1/workspace` without Authorization, account-selection, or conditional headers. It forwards Cookie, supplied Origin, and trusted platform `CF-Connecting-IP`. Only status 200 permits management HTML. Status 401 redirects to the existing prefixed `/auth/login`. Status 403 denies access, status 429 retains rate limiting, and other failures return 503. The probe has a five-second abort signal and no retry. Its private response body is cancelled without reading or storing it. Gated responses use `Cache-Control: private, no-store`.

The probe adds one backend request per management GET. Status 200 establishes an interactive session, not membership of a particular organization. Backend APIs must retain their own authorization checks. Confirm the bound backend's session-cookie contract before using this gate. Controlled tests cannot prove a deployed backend's contract or complete route coverage.

[Cloudflare routes take precedence over Custom Domains on the same hostname](https://developers.cloudflare.com/workers/configuration/routing/routes/). The [HTTP service binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/http/) reaches the backend directly. Keep workers.dev and preview URLs disabled for the gate, and independently verify alternate entry points on the backend. Do not place this gate in front of a different frontend responder or a public API host without checking its routing behavior.
